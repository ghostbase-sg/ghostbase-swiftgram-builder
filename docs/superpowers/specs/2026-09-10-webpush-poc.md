# Jerkgram Web Push PoC Specification

## Goal

Prove or disprove that Telegram Web Push (`account.registerDevice`, `token_type = 10`) can deliver Telegram message notifications to an iOS Home Screen web app whose PushSubscription was created on a Jerkgram-controlled HTTPS origin.

This PoC must not replace or modify Jerkgram's existing APNs/VoIP registration path.

## Upstream evidence

Telegram Web K (`morethanwords/tweb`, commit `e9428f2a90f73d750f16a0b85817820516466364`) creates a Web Push subscription with `pushManager.subscribe({ userVisibleOnly: true, applicationServerKey: VITE_PUSH_SERVER_KEY })` and registers the serialized PushSubscription with Telegram using `account.registerDevice` and `token_type = 10`.

The public application-server key used by Web K is:

`BB3JzmQIBTl8ZdTmLzhkZVnoYxoSvUmCe1CqqF53u2j0WbEFo2m--mOBagroDFdqMeESfz3ue1Z1e5PTIxMYH_g`

For the normal non-passcode path, Web K sends an empty `secret`. The subscription token is raw JSON, not a hex string.

Official Telegram iOS 12.9.2 (`TelegramMessenger/Telegram-iOS`, commit `6ad963e5b62d354da79040f388ae2b9132fb17b8`) currently supports only APNs type 1 and VoIP type 9 in `RegisterNotificationToken.swift`, and hex-encodes the native `Data` token. Therefore Web Push must use a separate raw-JSON registration helper.

## Architecture

1. A static HTTPS PWA creates a PushSubscription using Telegram Web K's public application-server key.
2. The PWA exposes `JSON.stringify(subscription.toJSON())` for copying.
3. Jerkgram registers that exact JSON with the authenticated Telegram account using `account.registerDevice` with:
   - `tokenType: 10`
   - `token: subscriptionJson`
   - `appSandbox: .boolFalse`
   - `secret: Buffer(data: Data())`
   - the caller-provided `otherUids`
4. Telegram, not Jerkgram, remains the Web Push sender.
5. The PWA service worker receives the push and displays a user-visible notification.

## Scope

In scope:
- isolated Web Push registration helper in TelegramCore;
- public TelegramEngine.AccountData wrapper;
- static PWA source staged in this branch;
- strict Python patcher, tests, and source verifier;
- optional later debug UI for pasting the subscription JSON only after the transport helper is verified.

Out of scope for this PoC:
- replacing normal APNs or VoIP registration;
- a Jerkgram push relay/server;
- storing Telegram auth keys on a Jerkgram server;
- encrypted/passcode Web Push secret handling;
- native Jerkgram notification attribution;
- production rollout;
- full Bazel build unless explicitly requested.

## Safety / rollback

All work is isolated on `dev/webpush-poc`. The current release branch is not modified. The patcher must fail closed when upstream anchors differ. Existing APNs and VoIP code must remain byte-for-byte semantically unchanged.

## Runtime success criteria

The PoC is only considered successful after all of the following happen on a physical iPhone:

1. The staged PWA is deployed to HTTPS.
2. It is added to the Home Screen and launched standalone.
3. Notification permission is granted from a user gesture.
4. A PushSubscription is created and its JSON is registered through the Jerkgram Web Push helper.
5. Jerkgram is backgrounded/suspended.
6. Another Telegram account sends a message.
7. A notification generated by the PWA service worker arrives without a Jerkgram-owned Telegram-session backend.

Passing static tests alone does not prove Telegram delivery to the custom origin.
